📘 Part 01 • Fundamentals

1. Introduction to OOP

1.1 What is Object Oriented Programming (OOP)?

DEFINITION: Object Oriented Programming (OOP) is a way of writing programs where we think of everything as an object, just like in real life. A student, a car, a bank account, a mobile phone — all of these are objects.

Every real-life object has two things:

  • Properties (data) — what the object has. Example: a car has a colour, a brand, and a speed.
  • Behaviours (actions) — what the object can do. Example: a car can start, stop, and accelerate.

In OOP, we keep the data and the actions together inside one unit. In Python, that unit is called a class. Python is a fully object-oriented language — even numbers, strings, and lists are objects.

💡 KEY IDEA: OOP = Data (attributes) + Actions (methods) packed together in one unit called a class. We then create many objects from that class.

1.2 Procedural Programming vs OOP

Before OOP, most beginners write procedural programs: a set of variables and a set of functions that work on those variables. This is fine for small programs, but when a program grows, the data and functions become scattered and hard to manage. OOP solves this by grouping them.

📘 Part 02 • Classes

2. Creating Classes

2.1 What is a Class?

A class is a blueprint (a plan) for creating objects. The class itself does not hold any real data — it only describes what data and actions its objects will have. When we create an object from a class, then real data is stored.

Think of a cookie cutter. The cutter is the class. The cookies made from it are the objects. One cutter can make hundreds of cookies, and each cookie can have its own decoration.

💡 KEY IDEA: A class is only a design. Memory for data is allocated when we create an object from it.

2.2 Syntax of a Class

class ClassName:
    "Optional docstring: describes the class"

    # class variable (shared by all objects)
    variable_name = 100

    # constructor
    def __init__(self, parameters):
        self.attribute = parameters # instance variable

    # method
    def method_name(self, parameters):
        # body of the method
        pass
📌 Program 4: Syntax of a Class (General Form)
Python Code • Program 4
class ClassName:
    """Optional docstring: describes the class"""

    # class variable (shared by all objects)
    variable_name = 100

    # constructor
    def __init__(self, parameters):
        self.attribute = parameters  # instance variable

    # method
    def method_name(self, parameters):
        # body of the method
        pass

# Showing that the docstring is stored inside the class
print(ClassName.__doc__)
🖥️ Output (Rendered ASCII Output)
Optional docstring: describes the class

Rules and conventions for writing a class:

  • Start with the keyword class, then the class name, then a colon.
  • By convention, class names use PascalCase (every word starts with a capital letter): Student, BankAccount, ElectricCar.
  • Variable and method names use snake_case: total_marks, show_details.
  • Every method in a class must have self as its first parameter.
  • The body of a class cannot be empty. If you have nothing to write yet, use the pass statement.

2.4 The Constructor __init__() and self

The method __init__() is called the constructor. Python runs it automatically the moment we create a new object. We use it to give starting values to the attributes of the object.

self is the first parameter of every method. It means "the object that is calling this method". When you write s1.show(), Python secretly sends s1 as self. You never pass self yourself.

class BankAccount:

Insufficient balance!
Account holder: Neha, Balance: 1200

How it works:

  • Methods can use and change the attributes of the object through self.
  • Logic like checking the balance lives inside the class, so it is always applied.

2.7 Printing an Object: __str__()

If you print an object directly, Python shows an ugly default text like <__main__.Student object at 0x...>. We can fix this by writing the special method __str__(), which returns a nice readable string.

📌 Program 11: Default Print vs __str__
Python Code • Program 11
class Book:
    def __init__(self, title, author):
        self.title = title
        self.author = author

class BetterBook:
    def __init__(self, title, author):
        self.title = title
        self.author = author

    def __str__(self):
        return f"'{self.title}' by {self.author}"

b1 = Book("Python Basics", "Rao")
b2 = BetterBook("Python Basics", "Rao")

print("Without __str__:", b1)
print("With __str__:", b2)
🖥️ Output (Rendered ASCII Output)
Without __str__: <__main__.Book object at 0x7f62e0f36cf0>
With __str__: 'Python Basics' by Rao

How it works:

  • __str__ must return a string (not print it).
  • print(b2) automatically calls b2.__str__().

3. Instance Objects

3.1 What is an Instance Object?

An object (also called an instance) is a real thing created from a class. Creating an object is called instantiation. If the class is the cookie cutter, the instance is the cookie.

We create an object by writing the class name followed by brackets, just like calling a function:

3.2 Every Object is Independent

Each instance has its own memory and its own copy of instance variables. Changing one object does not affect the other, even though both come from the same class.

📌 Program 13: Object Independence
Python Code • Program 13

        self.score += points

p1.add_score(5)
p2.add_score(30)

# They are two different objects in memory

🖥️ Output (Rendered ASCII Output)

Meera -> 30
Same object? False

How it works:

  • is checks whether two variables point to the very same object.
  • p1 and p2 are different objects, so changing p1.score never changes p2.score.

3.4 Two Names for One Object (Reference) vs Copy

When you write b = a, you do not create a new object. Both names now point to the same object. To get a real duplicate, use the copy module.

📌 Program 16: Reference and Copy
Python Code • Program 16
import copy

class Box:
    def __init__(self, items):
        self.items = items

a = Box(10)
b = a                  # b is just another name for the same object
c = copy.copy(a)       # c is a new, separate object

b.items = 99          # change through b

print("a.items:", a.items)  # a also changed
print("c.items:", c.items)  # c is not affected
print("a is b:", a is b)
print("a is c:", a is c)

a.items: 99
c.items: 10
a is b: True
a is c: False

How it works:

  • b = a copies only the reference (the address).
  • copy.copy(a) builds a new object with the same data.

3.5 Deleting Attributes and Objects

We can remove an attribute using del obj.attribute, and remove an object name using del obj. When no variable points to an object any more, Python deletes it from memory automatically (garbage collection). The special method __del__() runs just before this happens.

📌 Program 17: Deleting Attributes and Objects
Python Code • Program 17
class Demo:
    def __init__(self, name):
        self.name = name
        self.temp = "temporary data"
        print(self.name, "created")

    def __del__(self):
        print(self.name, "destroyed")

d = Demo("Object-1")

del d         # delete the object (destructor runs)
print("End of program")
🖥️ Output (Rendered ASCII Output)
Object-1 created
temp exists? False
Object-1 destroyed
End of program

How it works:

  • hasattr(obj, 'name') checks if an attribute exists.
  • __del__ is called when the last reference to the object is removed.
Remember: Class = blueprint (written once). Object = real instance (created many times). Each object has its own instance variables but shares the methods and class variables of its class.

4.3 Class Attributes vs Instance Attributes (Lookup Order)

When you write obj.name, Python searches in this order: first the object itself, then its class. If it is not found in either place, you get an AttributeError.

💡 KEY IDEA: If an object and its class both have an attribute with the same name, the object's own attribute wins. This is called shadowing.
📌 Program 23: Lookup Order and Shadowing

5.1 What is Inheritance?

Inheritance means that one class can take (inherit) all the attributes and methods of another class. In real life, a child inherits features from parents. In programming, the new class gets all the code of the old class without us writing it again. This is called code reuse.

TermAlso calledMeaning

    def parent_method(self):
        print("This method is in Parent")

class Child(Parent): # Child inherits from Parent
    def child_method(self):
        print("This method is in Child")

When the child class has its own __init__, the parent's __init__ is not called automatically. To run the parent constructor, we use super(). It means "go to my parent class".

📘 Part 06 • Overriding

6. Overriding Methods

6.1 What is Method Overriding?

When a child class inherits a method from its parent, the inherited version may not be perfect for the child. Method overriding means writing a method in the child class with the same name as the parent's method, so the child can give its own version of the work.

When we call the method on a child object, Python uses the child's version and ignores the parent's version. Overriding is how Python achieves runtime polymorphism.

Rules of overriding:

  • There must be inheritance (a parent and a child class).
  • The method name in the child must be exactly the same as in the parent.
  • The number of parameters should normally be the same, so that the method can be used in the same way.
  • The child's version replaces the parent's version only for the child's objects. Parent objects are not affected.
💡 KEY IDEA: Same method name + different body in the child class = Method Overriding.
📌 Program 37: Basic Method Overriding

📘 Part 07 • Encapsulation

7. Data Hiding

7.1 What is Data Hiding?

Data hiding means keeping the attributes of a class private, so that code outside the class cannot read or change them directly. It is part of encapsulation.

Think of an ATM. You can press buttons to withdraw money (methods), but you cannot open the machine and touch the cash (data). The machine hides its data and gives you only safe ways to use it.

Why do we need data hiding?

  • Security — nobody can set a wrong value, like a negative balance or an age of 500.
  • Control — we can check every value using a method before storing it.
  • Flexibility — we can change the inside code later without breaking the code that uses the class.

7.2 Access Levels in Python

Unlike Java or C++, Python has no keywords like private or public. Instead, Python uses underscores in names:

TypeNamingMeaningCan outside code use it?
PublicnameOpen for everyoneYes
Protected_name (one underscore)A hint: "for use inside the class and its children"Yes, but you should not
Private__name (two underscores)Hidden using name manglingNo, normal access gives an error
📌 Program 45: Public, Protected, and Private Attributes
Python Code • Program 45

        self.name = name        # public
        self._roll = roll       # protected (convention only)
        self.__marks = marks    # private (name mangling)

    def show(self):
        # inside the class, everything is accessible
        print(self.name, self._roll, self.__marks)

print(s._roll)    # works, but not recommended

try:

How it works:

  • Methods inside the class can use it freely.

7.3 Name Mangling: How Private Really Works

Python does not truly lock private attributes. It just renames them behind the scenes. An attribute __marks inside class Student is stored as _Student__marks. This is called name mangling. It stops accidental access, but a determined programmer can still reach it.

    def __init__(self, radius):
        self.__radius = radius

    @property
    def radius(self):
        return self.__radius

    @property
    def area(self):    # calculated value, no setter
        return 3.14 * self.__radius ** 2

c = Circle(5)
print("Radius:", c.radius)
print("Area:", c.area)

try:
    c.area = 100  # no setter defined
except AttributeError as e:
    print("Error: area is read-only")

Area: 78.5

How it works: A property without a setter is read-only. This is a neat way to protect values.

7.6 Private Methods and Inheritance

Methods can also be private. A private method (__method) is meant for use only inside its own class. A child class cannot call the parent's private members by their simple names, because of name mangling. A protected member (_name) is the right choice when children need access.

📌 Program 51: Private Method and Protected Attribute
Python Code • Program 51
class Parent:
    def __init__(self):
        self._protected = "I am protected"
        self.__private = "I am private"

    def __secret(self):
        return "Secret method"

    def reveal(self):
        return self.__secret()  # allowed inside the same class

class Child(Parent):
    def show(self):
        print(self._protected)  # OK: protected is open to children
        try:
            print(self.__private)  # not OK: becomes _Child__private
        except AttributeError:
            print("Child cannot access the parent's private attribute")

c = Child()
c.show()
print(c.reveal())
🖥️ Output (Rendered ASCII Output)
I am protected
Child cannot access the parent's private attribute
Secret method

How it works: Use _single for things children may need and __double for things only the class itself should touch.

Remember: Public: name | Protected: _name (convention) | Private: __name (name mangling). Use getters/setters or @property to control access.
📘 Part 08 • Overloading

8. Function Overloading

8.1 What is Function Overloading?

Function (or method) overloading means having several functions with the same name but with different parameters (different number or different types). The correct one is chosen depending on the arguments we send.

In languages like Java and C++, this is built in. For example, you can write add(int a, int b) and add(int a, int b, int c) together.

🔴 KEY IDEA: Python does NOT support traditional function overloading. If you define two functions with the same name, the LAST one replaces the earlier one.
📌 Program 52: Proof: The Second Definition Replaces the First
Python Code • Program 52
def add(a, b):
    return a + b

def add(a, b, c):  # replaces the first add()
    return a + b + c

print(add(1, 2, 3))  # works with 3 arguments

try:
    print(add(1, 2))  # the 2-argument version no longer exists
except TypeError as e:
    print("Error:", e)
🖥️ Output (Rendered ASCII Output)
6
Error: add() missing 1 required positional argument: 'c'

How it works: Only the last add (with three parameters) remains in memory.

But do not worry. Python gives us several simple techniques to get the same effect as overloading. Let us learn them one by one.

8.6 Technique 5: functools.singledispatch

The standard library module functools offers @singledispatch. We write one normal function and then register extra versions for different types of the first argument. Python chooses the correct version automatically, which is the closest thing to true overloading.

📌 Program 65: singledispatch
Python Code • Program 65
from functools import singledispatch

@singledispatch
def show(value):
    # default version
    print("Default:", value)

@show.register(int)
def _(value):
    print("Integer:", value + 1)

@show.register(str)
def _(value):
    print("String:", value.upper())

@show.register(list)
def _(value):
    print("List:", len(value), "items")

show(10)
show("python")
show([5, 6, 7])
show(2.5)  # float not registered -> default
🖥️ Output (Rendered ASCII Output)
Integer: 11
String: PYTHON
List: 3 items
Default: 2.5

How it works: @show.register(int) says: "use this version when the first argument is an int".

📌 Program 68: Overloading + and - for a Vector Class
Python Code • Program 68
class Vector:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __add__(self, other):
        return Vector(self.x + other.x, self.y + other.y)

    def __sub__(self, other):
        return Vector(self.x - other.x, self.y - other.y)

    def __str__(self):
        return f"({self.x}, {self.y})"

v1 = Vector(2, 3)
v2 = Vector(4, 1)

print("v1 + v2 =", v1 + v2)
print("v1 - v2 =", v1 - v2)
🖥️ Output (Rendered ASCII Output)
v1 + v2 = (6, 4)
v1 - v2 = (-2, 2)

How it works: v1 + v2 is secretly converted to v1.__add__(v2).

9.2 Common Mistakes to Avoid

  • Forgetting self as the first parameter of a method.
  • Writing __init__ with wrong spelling (it needs two underscores on each side).
  • Forgetting super().__init__() in the child's constructor.
  • Changing a class variable through self. instead of the class name.
  • Thinking b = a makes a copy of an object. It does not.
  • Believing __private is 100% secure. It is only name mangling.
  • Expecting two functions with the same name to both work in Python.
