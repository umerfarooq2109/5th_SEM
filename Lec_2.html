Part 01Memory & Names

Identifiers, Variables & The Python Memory Model

1.1 — What is an Identifier?

An identifier is the name you give to any entity in your program — a variable, function, class, module, or object — so that you (and the interpreter) can refer to it later.

Sticky Note vs Box Analogy

An identifier (variable name) is not the actual object. It is just a name that points to the object in memory.

• The Box: The object stored in memory (holds the data).
• The Sticky Note: The variable/identifier attached to the box.
The name on the sticky note tells Python which object you are referring to.

Why are identifiers needed? Computers store data at raw physical memory addresses like 0x7ffee23a1c4c, which are impossible for humans to memorize or work with at scale. Identifiers assign human-friendly labels to these memory locations, exactly like how a house has a complex geographic coordinate or street registration number, but people call it "Grandma's House" for conversational ease.

1.2 — Unicode Identifiers in Python 3

Python 3 allows Unicode characters in identifiers, meaning variable names can be written in different natural languages and mathematical scripts:

unicode_identifiers.py 
# Valid Unicode identifiers in Python 3
café = "coffee"
Δ = 5             # Greek Delta
北京 = "Beijing"    # Chinese characters

print(café)
print(Δ * 10)
print(北京)
Output
coffee
50
Beijing
Important Limitation

Python has strict rules about which Unicode characters can be used. For example, emojis (such as 🐍 or 🚀) are not allowed as identifiers in Python syntax and will raise a SyntaxError: invalid character in identifier.

1.3 — Lexer Rules for Valid Identifiers

These rules are strictly enforced by the Python lexer before your program ever runs:

  • Must start with a letter (a–z, A–Z) or an underscore (_) — never with a digit.
  • Remaining characters can be letters, digits (0–9), or underscores.
  • Cannot be a Python keyword (reserved words like if, while, class, for, def, True, None).
  • Case-sensitive: Age, age, and AGE are three completely separate identifiers.
  • No spaces or special symbols (@, -, %, $) allowed anywhere in the identifier.
valid_vs_invalid_identifiers.py 
# Valid identifiers
name = "Ayesha"
_count = 100
student1 = "Rahul"
total_marks = 95.5
_temp2 = True

# Invalid identifiers (uncommenting any line causes SyntaxError):
# 1name = "Error"       # Cannot start with digit
# total-marks = 90      # Hyphen '-' is treated as subtraction operator
# class = "Computer"    # 'class' is a reserved keyword
# my name = "Umer"      # Spaces are not allowed
# user@domain = "test"  # '@' is a special symbol (decorator syntax)

1.5 — Special Underscore Conventions

In Python, the underscore (_) is not just a character; it conveys critical semantics to the interpreter and developers:

1. Single Leading Underscore (_name) — "Internal Use Only"

A single underscore at the beginning indicates that a variable or function is intended for internal module/class use. While Python does not strictly enforce private access, it exhibits one crucial interpreter-level behavior:

module_underscore_demo.py 
# Inside my_module.py
name = "Akeel"
age = 20
_secret_key = "admin@123"   # Leading underscore

# If another file executes:
# from my_module import *
# Python automatically imports 'name' and 'age', but SKIPS '_secret_key'!
2. Single Trailing Underscore (name_) — "Avoid Keyword Conflicts"

When the most natural name for a variable happens to be a reserved Python keyword (such as class, def, type, in), PEP 8 recommends appending a single trailing underscore:

trailing_underscore_example.py 
# Invalid: class = "CSE"  --> SyntaxError: invalid syntax

# Valid PEP 8 convention:
class_ = "CSE 5th Sem"
type_ = "admin"
print(f"Registered: {class_}, Role: {type_}")
Output
Registered: CSE 5th Sem, Role: admin
3. Dunder Names (__name__) — "Interpreter Special Attributes"

Names surrounded by double underscores ("dunder" methods/attributes) are reserved for special Python system hooks. When a Python file is run directly from the command line, Python sets its internal __name__ variable to "__main__":

main_guard_demo.py 
def calculate_gpa(marks):
    return sum(marks) / len(marks)

if __name__ == "__main__":
    # This code ONLY executes if you run this file directly
    sample_marks = [85, 90, 78]
    print("Direct Execution GPA:", calculate_gpa(sample_marks))
Output
Direct Execution GPA: 84.33333333333333
1.6 — What is a Variable in Python?

In languages like C or C++, a variable is a labeled box — a fixed physical memory slot that directly stores raw binary bits, where the box type cannot ever change. In Python, a variable is a named reference (pointer) to an object existing in heap memory.

C Language (Box Model): Variable [ x ] (Type: int, Address: 0x1000) ──> Directly holds bits [ 00001010 ] Python (Tag / Pointer Model): Name Tag [ x ] ───────────────────────────────> Heap Object [ int: 10, id: 0x7fff4021 ]
The 3 Properties of Every Python Object

Every entity created in Python is an object with three immutable characteristics:
1. Identity (id): The unique memory address where the object resides (retrieved via id(x)).
2. Type: What data type it is (retrieved via type(x)).
3. Value: The actual data stored inside the object.

1.7 — The Balloon & String Tag Analogy

Think of objects in memory as balloons floating in a room, each balloon carrying a value. A variable name is a string tag with a label tied to a balloon:

  • x = 5 → "Take a balloon holding value 5, and tie a tag labeled x to it."
  • y = x → You do NOT create a new balloon. You tie a second tag, y, onto the exact same balloon. Both names share identical memory identity (id(x) == id(y)).
  • x = 10 → You untie tag x from balloon 5 and tie it to a brand-new balloon holding 10. Tag y remains securely attached to balloon 5.
  • If no tags point to balloon 5 anymore, Python's automatic Garbage Collector (GC) deallocates it to reclaim RAM.
memory_identity_demo.py 
x = 5
y = x
print("Same object?", id(x) == id(y))   # True
print("x is y?", x is y)               # True (identity comparison)

x = 10  # Rebinding tag x to a new object (10)
print("After rebinding x:")
print("x =", x, "| y =", y)
print("Same object now?", id(x) == id(y)) # False
Output
Same object? True
x is y? True
After rebinding x:
x = 10 | y = 5
Same object now? False
1.8 — What Happens When You "Change" a Variable?

When you write x = 10 followed by x = 20, you did NOT change the integer 10 into 20. In Python, integers are immutable (cannot be edited in-place):

  1. Python created an object 10, and pointed x at it.
  2. Python created a brand-new object 20, and moved the label x to point at 20.
  3. The old object 10 has zero active references and is swept away by garbage collection.
1.9 — Dynamic Typing Explained

Because variable names are merely untyped pointers and type information is stored inside the heap object itself, you can rebind the same name to objects of completely different types at runtime:

dynamic_typing_demo.py 
val = 100          # val references an 'int' object
print(val, type(val))

val = "Python"      # val now references a 'str' object
print(val, type(val))

val = [1, 2, 3]      # val now references a 'list' object
print(val, type(val))
Output
100 <class 'int'>
Python <class 'str'>
[1, 2, 3] <class 'list'>

Part 02Evaluation Engine

Assignment Statements & Types of Expressions

2.1 — Forms of Assignment Statements

An assignment statement binds a name (identifier) to an object using the = operator. Python supports three primary assignment patterns:

assignment_patterns.py 
# 1. Simple Assignment
x = 10

# 2. Chained Assignment (All names bound to the EXACT SAME object)
x = y = z = 0
print("Chained check:", id(x) == id(y) == id(z))  # True!

# 3. Simultaneous / Multiple Assignment (Tuple Unpacking)
a, b = 5, 10
print(f"Before swap: a={a}, b={b}")

# Swapping variables without a temporary third variable!
a, b = b, a
print(f"After swap:  a={a}, b={b}")
Output
Chained check: True
Before swap: a=5, b=10
After swap:  a=10, b=5
2.2 — The Critical "RHS-First" Evaluation Rule

When Python executes x = 5 + 3 or x = x + 1, the internal execution proceeds in two discrete stages:

  1. Right-Hand Side (RHS) is evaluated completely first: 5 + 3 → produces the integer object 8.
  2. Binding occurs second: Only after the object is fully created does Python bind the name on the left (x) to that resulting object.

This is why x = x + 1 works seamlessly: Python reads the old value of x, adds 1, produces a new integer object, and rebinds x to that new object.

A. Arithmetic Expressions

Arithmetic expressions combine numeric operands with mathematical operators to calculate a numeric result. Python strictly respects operator precedence (PEMDAS / BODMAS: Parentheses → Exponentiation ** → Multiplication/Division/Modulus * / // % → Addition/Subtraction + -).

B. Relational / Comparison Expressions

Relational expressions compare two operands and always evaluate to a Boolean value (True or False). Python uniquely supports chained comparisons (e.g., 10 <= score <= 100), which are evaluated efficiently from left to right with short-circuiting.

score = 85
passing_grade = 50

print("Equal (score == 85):", score == 85)            # True
print("Not Equal (score != 50):", score != 50)        # True
print("Greater Than (score > 90):", score > 90)        # False
print("Less Than or Equal (score <= 85):", score <= 85)# True

# Python Chained Comparison: 50 <= score <= 100

C. Logical Expressions

Logical expressions combine Boolean or truthy/falsy conditions using the keywords and, or, and not. Python uses short-circuit evaluation:
• and stops and returns the first falsy operand, or the last truthy operand if all are true.
• or stops and returns the first truthy operand, or the last falsy operand if all are false.

logical_expressions.py 
has_id = True
is_registered = False
is_admin = True

print("has_id and is_registered:", has_id and is_registered) # False
print("has_id or is_registered:", has_id or is_registered)   # True
print("not is_registered:", not is_registered)             # True

# Short-circuit value returning demo:
print("'Python' and 'Rocks':", "Python" and "Rocks") # Returns 'Rocks'
print("'' or 'Default':", "" or "Default")         # Returns 'Default'
Output
has_id and is_registered: False
has_id or is_registered: True
not is_registered: True
'Python' and 'Rocks': Rocks
'' or 'Default': Default

E. Assignment Expression (Walrus Operator :=)

Introduced in Python 3.8 (PEP 572), the walrus operator (:=) allows assigning a value to a variable as part of an expression, instead of requiring a separate statement. This eliminates duplicate calculations in loops and condition checks:

walrus_operator_demo.py 
# WITHOUT Walrus Operator (Traditional Way — computations repeated):
scores = [80, 95, 70, 88, 92]
n = len(scores)
if n > 3:
    print(f"Traditional Check: Processing {n} student scores.")

# WITH Walrus Operator (Assign & check in one single line):
if (total := sum(scores)) > 400:
    print(f"Walrus Check: Distinction cohort! Total marks = {total}")

# Classic use case: reading user input in a while loop
# while (user_input := input("Enter command: ")) != "quit":
#     print(f"Executing: {user_input}")
Output
Traditional Check: Processing 5 student scores.
Walrus Check: Distinction cohort! Total marks = 425
F. Bitwise Expressions

Bitwise expressions operate directly on the underlying binary bits of integer operands: AND (&), OR (|), XOR (^), NOT (~), Left Shift (<<), and Right Shift (>>).

Part 03Code Architecture

Named Constants & Python Keywords

3.1 — What is a Named Constant?

A named constant is an identifier whose assigned value is intended to remain fixed throughout the entire lifecycle of a program. It is assigned a descriptive name so that the code is self-explanatory, and if business logic changes, the value only needs to be updated in one centralized place.

Convention vs Hardware Enforcement

Unlike languages such as C++ (const) or Java (final), Python does not have a built-in keyword that prevents reassignment. Constants in Python are governed by strong developer convention: writing the identifier in ALL_CAPS signals "Do not touch or reassign this value."

3.2 — Why We Use Constants (The 3 Pillars)
  • Eliminating Magic Numbers: Writing if age >= 18: is ambiguous; writing if age >= LEGAL_VOTING_AGE: is completely self-documenting.
  • Centralized Maintainability: If a tax rate changes from 5% to 8%, you change one single line (GST_RATE = 0.08) at the top of your module rather than hunting for every rogue 0.05 across 10,000 lines of code.
  • Preventing Silent Bugs: Grouping fixed parameters together avoids accidental typo discrepancies across different calculation modules.
3.3 — Where Constants are Declared

In professional engineering practice, constants are placed:

  • At the top of a script file (directly below docstrings and imports).
  • Inside a dedicated configuration file, such as config.py or constants.py, and imported across the project.
constants_config_demo.py 
# config.py — Centralized project settings
DATABASE_PORT = 5432
MAX_CONNECTIONS = 100
PI = 3.141592653589793
APP_NAME = "SSM Student Portal"

def compute_circle_area(radius):
    return PI * (radius ** 2)

print(f"{APP_NAME} | DB Port: {DATABASE_PORT}")
print("Circle Area (r=7):", compute_circle_area(7))
Output
SSM Student Portal | DB Port: 5432
Circle Area (r=7): 153.93804002589985

Part 04Hardware & Bit Architecture

Numeric Data Types & The Deep Dive on IEEE-754 Floats

4.1 — Built-in Numeric Types in Python

Python provides three distinct built-in numeric data types:

  • int (Integer): Whole numbers (positive, negative, zero) of arbitrary precision.
  • float (Floating-Point): Real decimal numbers represented internally via the IEEE-754 double precision (64-bit) standard.
  • complex (Complex Numbers): Numbers consisting of a real and imaginary component (a + bj).
4.2 — Integers & Arbitrary Precision

In languages like C or Java, an integer has a fixed bit-width (e.g., 32-bit: -2,147,483,648 to +2,147,483,647). Exceeding this boundary causes a catastrophic integer overflow. In Python, integers have no fixed maximum size. CPython stores large integers dynamically as an array of digits in heap memory, bounded solely by available system RAM.

integer_bases_and_precision.py 
# 1. Arbitrary Precision — No Overflow!
huge_num = 123456789012345678901234567890 ** 2
print("Huge square:", huge_num)

# 2. Integer Literals in Different Number Bases:
dec = 100          # Decimal (Base 10)
bin_val = 0b1010    # Binary (Base 2, prefix 0b) -> 10
oct_val = 0o17      # Octal (Base 8, prefix 0o)   -> 15
hex_val = 0x1A      # Hexadecimal (Base 16, prefix 0x) -> 26

print(f"Bases: Bin={bin_val}, Oct={oct_val}, Hex={hex_val}")

# 3. Visual separator underscores (Python 3.6+)
salary = 1_500_000   # Exactly equal to 1500000
print("Salary formatted:", salary)
Output
Huge square: 152415787532388367504953515183000000000000000000000000000000
Bases: Bin=10, Oct=15, Hex=26
Salary formatted: 1500000
4.3 — The Hardware Problem: How Numbers are Stored

Inside a computer CPU, data is physically stored in hardware registers composed of electronic circuits called flip-flops. A flip-flop is bistable: it can only physically hold voltage states representing 0 or 1.

  • An integer like 4 is stored directly as binary 0100.
  • A float like 4.0 or 2.5 presents a hardware crisis: a flip-flop cannot physically hold a decimal point or dot (.)!
  • Therefore, no computer ever stores a decimal point directly in silicon registers. It stores a normalized mathematical representation!
4.4 — Fixed-Point vs Floating-Point Numbers
Aspect Fixed-Point Representation Floating-Point Representation
Point Position Predefined, fixed position (e.g., always 2 decimal places) Variable position — the point "floats" dynamically
How Handled Ignore the dot, calculate on whole digits, reinsert dot on display Requires mathematical Normalization into Sign, Exponent, Mantissa
Examples 7.32 + 3.25 + 6.52 → 732 + 325 + 652 = 1708 → 17.08 73.2, 649.0, 0.00101, 5.63
Limitation Cannot scale to both microscopic and astronomical numbers Handles vast ranges, but subject to binary fractional precision rounding
4.5 — The Normalization Process

Normalization is the process of converting any floating-point number into a standard form so that the decimal point always appears at one predictable, canonical position.

Rule of Normalization

Decimal Normalization Rule: There must be exactly one non-zero digit to the left of the decimal point.
• 73.2 → 7.32 × 10¹
• 649.0 → 6.49 × 10²
• 5.63 → 5.63 × 10⁰ (Already normalized)
• 0.00847 → 8.47 × 10⁻³

Once normalized, any number is completely defined by two components:

  • Mantissa: The digits of the number without the point (defines the significance/precision).
  • Exponent: The power that specifies how far and in which direction the point must shift.
4.6 — Binary Normalization & The "Hidden Leading 1" Trick

In base-2 (binary), there is only one non-zero digit: 1. Therefore, every single normalized binary number without exception begins with 1.:

Normalized Binary Formula: 1 . (mantissa_bits) × 2^(exponent)
Why the Leading 1 is NOT Stored in Hardware

Since every normalized binary number always begins with 1., storing that leading 1 would waste 1 bit of precious silicon register space. IEEE-754 hardware simply assumes this implicit leading 1 and only stores the fractional bits after the point. This gives 53 bits of effective precision while only storing 52 bits!

Original Binary Number Normalized Form True Exponent Stored Mantissa (Leading 1 dropped)
101.1011 1.011011 × 2² +2 (point moved 2 left) 011011
11111.01 1.111101 × 2⁴ +4 (point moved 4 left) 111101
0.00101 1.01 × 2⁻³ -3 (point moved 3 right) 01
-10.01 -1.001 × 2¹ +1 (point moved 1 left) 001 (Sign S=1)
4.7 — IEEE-754 64-Bit Double-Precision Standard

Python floats use the standard 64-bit IEEE-754 format. A 64-bit register is partitioned into three fields:

Field Bit Width Function Formula / Value
Sign (S) 1 bit (Bit 63) Determines positive or negative S = 0 (+) | S = 1 (-) → (-1)^S
Biased Exponent (E) 11 bits (Bits 62–52) Stores power of 2 with bias offset Biased_E = True_E + 1023 (Bias for 64-bit)
Mantissa (M) 52 bits (Bits 51–0) Stores fractional bits after "1." 52 bits (padded with trailing zeros)
4.8 — Full Worked Example: Encoding 0.001001₂ in 64-bit IEEE 754

Let's follow the exact engineering procedure to encode 0.001001₂ into 64-bit IEEE 754:

  1. Step 1 (Normalize): Shift the point 3 positions to the right → 1.001 × 2⁻³ (True Exponent = -3).
  2. Step 2 (Sign Bit): Number is positive → S = 0.
  3. Step 3 (Biased Exponent): Biased E = True E + Bias = -3 + 1023 = 1020.
    Convert 1020 to 11-bit binary → 01111111100₂.
  4. Step 4 (Mantissa): Drop the leading 1 from 1.001 → keep 001.
    Pad with 49 trailing zeros to fill 52 bits → 0010000000000000000000000000000000000000000000000000.
  5. Step 5 (Full 64-bit Output):
    0 | 01111111100 | 0010000000000000000000000000000000000000000000000000
4.9 — Full Worked Reversal: Decoding 64-bit IEEE 754 Back to Decimal

Given the stored 64-bit register pattern above, we reverse the decoding pipeline step by step:

  1. Sign: S = 0 → (-1)⁰ = +1.
  2. Exponent: Stored 01111111100₂ = 1020 → True E = 1020 - 1023 = -3.
  3. Mantissa: Restore the hidden leading 1 → 1.001₂.
  4. Un-normalize: Shift the point 3 places left → 0.001001₂.
  5. Convert to Decimal: 0×2⁻¹ + 0×2⁻² + 1×2⁻³ + 0×2⁻⁴ + 0×2⁻⁵ + 1×2⁻⁶ = 1/8 + 1/64 = 0.125 + 0.015625 = 0.140625₁₀.
4.10 — The Famous Mystery: Why 0.1 + 0.2 = 0.30000000000000004

In Python (and virtually every modern programming language), typing 0.1 + 0.2 produces 0.30000000000000004. This is not a Python bug — it is a mathematical property of base-2 fractional representation.

Base-10 vs Base-2 Repeating Fractions

In decimal, 1/3 produces the infinitely repeating fraction 0.333333.... No finite number of decimal digits can ever write 1/3 exactly.

Similarly, in binary, the numbers 0.1₁₀ and 0.2₁₀ produce infinitely repeating binary fractions:
• 0.1₁₀ = 0.00011001100110011...₂ (repeats '0011' forever)
• 0.2₁₀ = 0.0011001100110011...₂ (repeats '0011' forever)

Step Operation (Converting 0.1 to Binary) Binary Digit Remaining Fraction
1 0.1 × 2 = 0.2 0 0.2
2 0.2 × 2 = 0.4 0 0.4
3 0.4 × 2 = 0.8 0 0.8
4 0.8 × 2 = 1.6 1 0.6
5 0.6 × 2 = 1.2 1 0.2
6 0.2 × 2 = 0.4 0 0.4 (Pattern Repeats from Step 2!)

Because the 64-bit double precision mantissa only holds 52 bits, the infinite repeating pattern is truncated and rounded at bit 52. When added together and converted back to decimal for display, the tiny accumulated rounding difference shows up as 0.30000000000000004.

float_precision_handling.py 
import math
from decimal import Decimal

# 1. The Precision Quirk
raw_sum = 0.1 + 0.2
print("0.1 + 0.2 =", raw_sum)
print("Is 0.1 + 0.2 == 0.3?", raw_sum == 0.3)  # False!

# Solution 1: round() for display
print("Using round():", round(raw_sum, 2))

# Solution 2: math.isclose() for safe comparison in conditions
print("Using math.isclose():", math.isclose(raw_sum, 0.3)) # True!

# Solution 3: decimal.Decimal for financial/banking accuracy
d1 = Decimal('0.1')
d2 = Decimal('0.2')
print("Decimal Exact Sum:", d1 + d2)  # Exactly 0.3
Output

4.12 — Numeric Type Conversion & Implicit Coercion

When different numeric types interact in an expression, Python applies implicit type coercion by widening to the more precise type in the hierarchy:

The Boolean Type & Truthy / Falsy Evaluation

5.1 — What is a Boolean?

A Boolean is a data type in Python that can hold only two possible values: True or False. It is named after George Boole, a 19th-century mathematician who formalized algebraic logic. In simple terms, a Boolean answers a binary "yes or no" proposition.

Critical Architectural Fact: bool is a Subclass of int

In Python, the bool type is technically a subclass of int. This means:
• True has an underlying integer value of 1.
• False has an underlying integer value of 0.
• isinstance(True, int) returns True.

bool_subclass_int_proof.py 
print("True + True =", True + True)     # 1 + 1 = 2
print("False + 5   =", False + 5)       # 0 + 5 = 5
print("True == 1   :", True == 1)       # True
print("False == 0  :", False == 0)      # True
print("isinstance(True, int):", isinstance(True, int)) # True
Output
True + True = 2
False + 5   = 5
True == 1   : True
False == 0  : True
isinstance(True, int): True
5.2 — Truthy and Falsy Values

Python does not merely test explicit True and False values in conditionals (if, while) — it evaluates any object's inherent truthiness.

Classification Values Behavior in 'if' Condition
Falsy Values False, None, 0, 0.0, 0j, "" (empty string), [] (empty list), {} (empty dict), () (empty tuple), set() (empty set) Evaluates to False (block does not execute)
Truthy Values Any non-zero number (e.g., 5, -10, 0.1)
Any non-empty string (e.g., "Python", " " with a space, "0", "False")
Any non-empty collection (e.g., [0], {'key': 'val'}) 		Evaluates to True (block executes)
Classic Beginner Trap

The string "False" (enclosed in quotes) is TRUTHY! Because it is a non-empty string of 5 characters. Only the keyword False (without quotes) is falsy.

truthy_falsy_in_action.py 
# 1. Empty container check
cart = []
if not cart:
    print("Cart is empty! Please add items.")

# 2. String truthiness check
text1 = "False"   # Non-empty string -> Truthy!
text2 = ""        # Empty string -> Falsy!

print("bool('False') =", bool(text1))  # True
print("bool('')      =", bool(text2))  # False
print("bool('0')     =", bool("0"))    # True
print("bool(None)    =", bool(None))   # False
print("bool([0])     =", bool([0]))    # True (list contains 1 item)
Output
Cart is empty! Please add items.
bool('False') = True
bool('')      = False
bool('0')     = True
bool(None)    = False
bool([0])     = True
5.3 — Key Points to Remember for Exams & Interviews
  • bool is a direct subclass of int (True == 1, False == 0).
  • Python is strictly case-sensitive: true and false do not exist and will raise NameError; only True and False are valid.
  • Comparison operators (==, !=, <, >, <=, >=) always return a pure Boolean.
  • Logical operators (and, or) return the actual operand that determined the result (short-circuiting).
  • bool() without arguments returns False.

Lecture 2 Summary & Key Takeaways

In this lecture, we unpacked the core foundation of Python's data representation and runtime mechanics:

  • Identifiers & Variables: Python variables are names pointing to heap objects (the balloon & tag model). Integers are immutable; variables are dynamically typed references.
  • Assignments & Expressions: Assignment statements follow the RHS-first evaluation rule. Expressions always reduce to a single value across arithmetic, comparison, logical, string, and walrus (:=) categories.

  • IEEE-754 Floating-Point: Because CPU flip-flops cannot hold decimal points, floats use normalization into Sign, Biased Exponent, and Mantissa with a hidden leading 1. Infinitely repeating binary fractions explain why 0.1 + 0.2 != 0.3.
  • Boolean Logic: bool subclasses int (True == 1). Conditionals evaluate truthiness, where only empty collections, 0, None, and False are falsy.
